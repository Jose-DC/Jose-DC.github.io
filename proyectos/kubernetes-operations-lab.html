Laboratorio local · Etapa 1 en desarrollo

Laboratorio de Operación y Respuesta a Incidentes en Kubernetes

Proyecto incremental para construir una línea base observable antes de provocar fallas: una aplicación visual desplegada con Docker y Helm que permite comprobar tienda, versión, release, namespace, pod y estado de salud.

Volver a proyectos

Problema que resuelve

Un pod Running no cuenta toda la historia

Ver un pod en ejecución no permite saber qué configuración recibió, qué versión atiende tráfico, qué réplica respondió ni si la aplicación está realmente preparada. Sin esa línea base es fácil diagnosticar con supuestos.

Método

Observar antes de introducir fallas

Primero se valida una instancia saludable. Helm entrega la configuración de la tienda, Kubernetes inyecta la identidad del pod y la aplicación expone panel, JSON, health checks, métricas y logs coherentes.

Alcance actual

Una tienda y una línea base local

La Etapa 1 usa datos ficticios y una sola release en Kubernetes local. Múltiples tiendas, Ansible, incidentes, Prometheus/Grafana, CI y AKS permanecen pendientes.

Etapa actual

Etapa 1 · Construir una línea base observable

Esta es la única etapa activa. Su cierre requiere comprobar aplicación, imagen, chart y despliegue local antes de agregar tiendas o incidentes.

La ruta principal muestra Tienda Demo, versión, ambiente, release Helm, namespace, pod, nodo, IP, tiempo activo, solicitudes y readiness. Los mismos datos quedan disponibles en JSON para validación técnica.

Validación pendiente

Ejecutar y reunir evidencia de la línea base

El código y la configuración están preparados. La Etapa 1 se marcará como validada únicamente después de ejecutar la aplicación, construir la imagen, desplegar la release y comprobar el panel contra el estado real de Kubernetes.

Límites actuales

Lo que todavía no afirma este proyecto

  • No es una aplicación de punto de venta ni incluye datos reales.
  • No demuestra multi-tenancy, alta disponibilidad ni aislamiento productivo.
  • No incluye aún incidentes ejecutados, dashboards, alertas ni CI/CD.
  • Se ejecuta en Kubernetes local; no representa un despliegue de AKS.
