Caso de experiencia laboral

Despliegues en AKS con Azure DevOps

Diseñé e implementé automatizaciones con Azure DevOps para ejecutar despliegues en AKS con validaciones, revisión y trazabilidad. Este caso explica las decisiones técnicas y los problemas que resolví, sin exponer código ni información interna.

Volver a proyectos

El desafío

De tareas manuales a un proceso más ordenado

En la operación de aplicaciones sobre Kubernetes, tareas como publicar una versión, preparar una nueva instancia o volver a una versión anterior requerían ejecutar scripts manualmente. Cada cambio exigía identificar el destino correcto, seleccionar la versión y revisar el resultado. Al depender de pasos repetidos desde un equipo, era más difícil mantener un proceso consistente y saber después qué se había ejecutado.

La solución

Automatización con puntos de control

El objetivo fue convertir esas tareas en un proceso repetible y revisable. Diseñé pipelines en Azure DevOps y scripts de PowerShell que integran el registro de imágenes, Helm y herramientas de Kubernetes para preparar y ejecutar cambios en AKS. La solución permite simular un cambio, revisar el plan y ejecutar la aplicación por separado, con aprobación y registro.

Alcance

Qué permite hacer la solución

El trabajo abarcó distintas etapas del ciclo de despliegue, desde preparar una versión hasta apoyar su recuperación. Estas capacidades se presentan agrupadas para explicar el alcance sin reproducir la configuración interna.

Preparar una versión

Automatizar la construcción y publicación de imágenes de aplicación en un registro de contenedores para tener una versión disponible para desplegar.

Desplegar y actualizar

Apoyar la creación y actualización de instancias en Kubernetes, usando Helm y parámetros validados para seleccionar el cambio que se quiere realizar.

Recuperar una versión

Apoyar el retorno a una imagen anterior cuando sea necesario, con comprobaciones para identificar si el cambio solicitado tiene sentido.

Decisión técnica

Una recuperación debe cambiar algo

Detecté un caso en que dos revisiones consecutivas de Helm podían apuntar a la misma imagen. Volver a la revisión anterior no necesariamente recuperaba la versión esperada.

Mejoré la selección para buscar una revisión con una imagen distinta y agregué una prueba para ese escenario. También reforcé las validaciones para detectar operaciones que no producirían el cambio esperado.

Mi aporte

Cómo preparé los despliegues

Trabajé en la automatización y en los controles que permiten revisar un cambio antes de ejecutarlo.

Parámetros y validación

Organicé la selección del destino y la versión con opciones predefinidas y validaciones previas, para reducir errores al ingresar datos.

Revisión antes de aplicar

Incorporé una simulación para revisar el cambio. La aplicación se inicia por separado y contempla aprobación y comprobaciones previas.

Registro y seguimiento

Las ejecuciones conservan información sobre el plan y el resultado, facilitando la revisión posterior y el diagnóstico de errores.

Manejo de errores

Agregué comprobaciones para detener operaciones que no cumplen las condiciones esperadas y comunicar los fallos durante la ejecución.

Acceso controlado

Consideré permisos acotados para las tareas de automatización y la protección de credenciales usadas por las integraciones.

Recuperación

Revisé escenarios de retorno a versiones anteriores y sus límites, considerando que una reversión de imagen no recupera datos.

Integración

Desarrollo y producción tienen necesidades distintas

Para desarrollo creé un workflow de GitHub Actions que inicia un pipeline de Azure DevOps y comunica si su ejecución falla. Para operaciones en producción preparé flujos de ejecución manual con revisión y aprobación.

Resultado

Un proceso más fácil de revisar y repetir

El trabajo permitió desarrollar automatizaciones centralizadas para tareas que antes se ejecutaban manualmente, con una forma de revisar los cambios y consultar sus resultados. No se presentan cifras de reducción de tiempo o errores.

En la implementación combiné desarrollo de scripts, integración de herramientas, revisión de fallos y pruebas de escenarios específicos. El valor del caso está tanto en automatizar como en considerar la operación y la recuperación.

Validación y alcance

Automatizar no reemplaza la validación funcional

  • Pruebas locales: desarrollé pruebas para scripts y escenarios de error, incluido el caso de recuperación descrito arriba. Las pruebas con servicios simulados no validan por sí solas el comportamiento en AKS.
  • Validación en el entorno: la ejecución del pipeline y la disponibilidad de los recursos no confirman por sí solas que la aplicación funcione correctamente; se requiere una comprobación funcional posterior.
  • Recuperación: volver a una imagen anterior no revierte los datos. La recuperación debe considerar también el estado de la aplicación.
  • Código privado: este es un caso de experiencia laboral; no publico el repositorio ni detalles internos. Los diagramas son conceptuales.
